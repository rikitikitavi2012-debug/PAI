🗒️ TASK: Что такое DocCrossRef и что пропущено
📃 CONTENT:

**Что это:** Автоматический "доктор документации". При завершении сессии (Stop hook) проверяет что документы (CLAUDE.md, CONTEXT_ROUTING.md, etc.) соответствуют реальному коду.

**Две фазы:**
1. **Детерминистическая (Layer 1)** — работала всегда:
   - Считает hook-файлы на диске vs "30 hooks" в доках → обновляет число
   - Проверяет что пути в документации реально существуют
   - Обновляет timestamps

2. **AI-фаза (Layer 2)** — **не работала ни разу** из-за бага:
   - Sonnet читает изменённый код + документацию
   - Находит **семантический дрифт** — когда описание в доках больше не соответствует поведению кода
   - Генерирует хирургические правки (`old_text → new_text`)

**Что пропустили из-за бага:**

Каждая сессия где менялись hooks/PAI/skills — AI-проверка молча фейлилась. Доки не обновлялись автоматически. Конкретно:

- **CONTEXT_ROUTING.md** — мог накопить битые ссылки (Jules уже фиксил часть — PR #883)
- **CLAUDE.md** — описания хуков могли разойтись с реальностью (мы вручную обновляли MEMORY.md, но не системные доки)
- **PAI/Algorithm** — описания фаз могли устареть
- Все `doc-drift-state.json` отчёты — без AI-анализа, только детерминистика

По сути: **нервная система PAI работала на одном глазу**. Механические проверки ловили только битые пути и неправильные числа, а смысловые расхождения проходили незамеченными.

Теперь с фиксом — Layer 2 заработает со следующей сессии.

🗣️ Navi: DocCrossRef — автодоктор документации. AI-фаза не работала с момента создания. Детерминистика ловила только битые пути, а смысловой дрифт копился незамеченным.
