## Active Strategies

### S0: Learn-by-doing (Учусь через практику)
**Адресует:** C0 (нехватка навыков), G0, G2
**Принцип:** Практика важнее теории. Учусь на ходу, делая реальные проекты вместо бесконечного изучения.
**Реализация:**
1. Берусь за проект (Цифровой Прораб PWA, МАФ сайт)
2. Решаю проблемы по мере их появления
3. Фиксирую уроки в TELOS (LEARNED.md)
4. Итерация — каждый следующий проект лучше предыдущего

### S1: AI-автоматизация (Агенты вместо ручного труда)
**Адресует:** C1 (нехватка времени), G0, G2, G10
**Принцип:** Делегируй AI то, что другие делают вручную. PAI + Agent Zero + Venice AI = мультипликатор продуктивности.
**Реализация:**
1. PAI v4.0.3: 31 хук, 235 тестов, 13 скиллов, security system — всё активно
2. **AI Brigade — 5 T1 автономных агентов, все в PAI контексте (2026-03-12):**
   - **Navi** (Claude Code) — архитектор, тимлид. Контекст: CLAUDE.md + loadAtStartup
   - **Jules** (Google) — async-кодер: тесты, баги, фиксы. Контекст: AGENTS.md в repo
   - **Agent Zero** — 24/7 VPS Docker. Контекст: system prompt + FAISS memory + per-task от Navi
   - **Gemini CLI** — second opinion, research, TF контент. Контекст: GEMINI.md + symlinks + hooks
   - **OpenCode CLI** — мульти-провайдер кодер, EXA search. Контекст: AGENTS.md + plugin + symlinks
3. **Инструменты T3 (вызываются членами бригады):**
   - **Inference.ts** — unified API для 5 LLM: fast/standard/smart/gemini/glm5
   - **GLM-5 / zai-cli** — inference provider + MCP tools (vision, search, read). Резерв при блокировках
   - **JulesAutoMerge.ts** — pipeline: тесты в worktree → A0 code review → merge
   - **CommunityCheck.ts** — мониторинг upstream PRs/issues
   - **MCP серверы** — расширения Claude Code (filesystem, fetch)
4. Venice AI (через A0T стейкинг) — приватные LLM без цензуры
5. Каждую повторяющуюся задачу автоматизировать через агента или инструмент
6. Test harness для хуков — сеть безопасности при изменениях (235 тестов / 40 сюит)
7. Feedback loop: RatingCapture → WisdomSync → FRAMES — автоматическое обучение
8. Hook performance optimization: SecurityValidator 282→26ms, UpdateTabTitle 10s→<500ms

### S2: Ступенчатый рост (Найм → Накопления → Инвестиции → Бизнес)
**Адресует:** C2 (финансовая зависимость), G1, G3, M0
**Принцип:** Не прыгать в бизнес без подушки. Использовать стабильный доход от найма для накопления и тестирования идей.
**Реализация:**
1. Работа прорабом — стабильный доход
2. Накопления (3.5 млн ₽) — инвестирование по плану
3. Параллельно — запуск бизнеса МАФ
4. При достижении дохода от МАФ > зарплаты — уход из найма

### S3: Инфраструктурная независимость (Обход блокировок)
**Адресует:** C2 (Технологическая изоляция РФ), G6, G9, M3
**Принцип:** Не зависеть от одного провайдера/страны. Иметь резервные каналы для всего.
**Реализация:**
1. VPS Timeweb (Нидерланды) — 2 сервера: шлюз + Agent Zero
2. A0T стейкинг → Venice AI API (приватные LLM, без блокировок)
3. SSH-туннели + http-proxy-to-socks для обхода ограничений (Anthropic + Google)
4. Z.AI (Zhipu AI, Китай) — прямой доступ без прокси. GLM-5 + MCP tools (vision, search, read). Стратегический резерв: если заблокируют Anthropic и Google — Zhipu остаётся
4. Для дома в горах: FTTH Ростелеком + резервный Мегафон 4G + Peplink bonding

**Принцип:** Не класть все яйца в одну корзину. Распределять капитал по нескольким классам активов.
**Реализация:** См. секцию "Распределение капитала" ниже.

### S5: Акции > Железо (Инвестиции в полупроводники)
**Адресует:** G8, M0
**Принцип:** Железо обесценивается на 60-70% за 3 года. Акции производителей (NVIDIA, Micron, AMD) растут на 200-400%. Инвестировать в акции, а не в физическое железо.
**Реализация:**
1. Портфель акций: NVIDIA (25%), Micron (20%), AMD (20%), SK Hynix (20%), Samsung (15%)
2. Cloud GPU (RunPod, Vast.ai) — вместо покупки физического железа
3. Мониторинг DDR5/HBM дефицита — корреляция с ростом акций
4. Горизонт инвестиций: 3-5 лет

### S6: Timber Frame фокус (узкая ниша вместо массового рынка)
**Адресует:** G1 (Бизнес TF), G3 (Финансовая независимость), M0 (Независимость)
**Принцип:** Не конкурировать в массовом сегменте террас (6-25К ₽/м²). Занять пустую нишу Timber Frame малых форм (50-120К ₽/м²) в СПб. 5 целевых заявок лучше 50 нецелевых.
**Реализация:**
1. Партнёрство с Шульцем — 3D SketchUp + мастерство TF каркасов
2. Сайт с премиум-позиционированием (визуал, 3D, высокий ценовой якорь)
3. SEO на нишевые запросы ("timber frame терраса СПб", "фахверк веранда")
4. Отсечение эконом-сегмента через подачу и ценообразование
5. Продуктовая линейка: TF Терраса → TF Веранда → TF Навес → TF Пергола
6. **TF Knowledge Base** (март 2026) — систематическая экспертность мирового уровня:
   - 7 файлов: мастера (15 мировых + 4 российских), 12 соединений с инженерным "ПОЧЕМУ", 10 типологий, 16 книг, хронология 7000 лет, стандарты (TFEC, Eurocode 5, NDS, DIN 1052)
   - Конкурентный ров: ни один конкурент в РФ не демонстрирует понимание "ПОЧЕМУ каждое соединение", не ссылается на мировых мастеров, не знает стандартов
   - Личный контакт с Павлом Притупом (через Виктора Шульца) — единственный TF мастер-преподаватель в России
   - Позиционирование: не "продаём террасы" → "работаем в мировой традиции timber framing" (Benson, Sobon, Chappell → Притуп → мы)
7. **Экспертный контент** — принцип "ПОЧЕМУ, а не ЧТО" во всех материалах. Каждое решение объясняется через причинно-следственные связи. Ссылки на мастеров и книги как доказательство глубины
**Обоснование:** Конкурентная разведка (21.02.2026) подтвердила: ни одна компания в СПб не предлагает TF террасы/веранды как отдельный премиум-продукт. Ценовой GAP 25-50К ₽/м² пуст.
**Урок 2025:** Массовая реклама без фокуса = слив бюджета (1 закрытая нецелевая заявка).
**Усиление 2026-03:** Knowledge base + связь с Притупом = экспертное позиционирование на мировом уровне. Конкуренты продают "фахверк" как стиль, мы — как ремесло с 7000-летней историей.

### S7: Open Source Community (вклад в upstream PAI)
**Адресует:** G10 (аудит скиллов), G11 (community contribution), M1 (Инновации), M3 (Техно-суверенитет)
**Принцип:** Контрибьюция в open source = обучение + репутация + влияние на инструмент, от которого зависишь. Баги найденные в своей системе → фиксы для всего community. Двойная выгода: улучшаешь свой PAI и зарабатываешь авторитет.
**Реализация:**
1. Мониторинг upstream через CommunityCheck.ts (6-час кэш, gh CLI)
2. Баги и улучшения → PR через worktree workflow (main branch → feature branch → PR)
3. Локальные фиксы → upstream PR (RatingCapture, algorithm, test harness)
4. Code review чужих PRs для обучения и видимости
5. Issues с документацией багов для тех что не можем пофиксить сами
6. Jules для batch-генерации тестов и документации — PR в upstream PAI через feature branches
7. Navi автоматически подаёт upstream PRs от имени "Navi, PAI agent of Ivan" (#882, #883)
**Результаты:** 8 PRs за 3 недели, contributor acknowledgment в release notes v4.0.3
**Обоснование:** Ivan зависит от PAI как инфраструктуры. Влияние на upstream = контроль над направлением развития. Репутация контрибьютора = доверие community.
