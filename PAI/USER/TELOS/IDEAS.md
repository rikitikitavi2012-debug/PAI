## Активные идеи

### I0: Construction Orchestrator на Agent Zero для ниши МАФ
**Категория:** Продукт / Бизнес
**Статус:** Разработка концепции
**Описание:** AI-платформа для строительного бизнеса в нише МАФ (малые архитектурные формы — беседки, перголы, навесы, детские площадки). Сначала отработать структуру и подходы на МАФ, затем расширить на другие строительные ниши. Технология: Agent Zero + PAI.
**Почему интересно:** МАФ стандартизирован (типовые размеры, узлы, материалы) — идеален для AI-автоматизации. Blue Ocean — нет прямых аналогов в РФ. 10+ лет экспертизы = конкурентный ров.
**Следующий шаг:** PWA приложение (P3) → валидация на своей фирме → SaaS
**Связано с:** G2 (Construction Orchestrator SaaS), M1 (Инновации), B5 (вечные ниши)

**RedTeam анализ (8 агентов, 2026-02-20):**
- **Сила (4/8 агентов подтвердили):** Доменная экспертиза 10+ лет — защитный ров, который нельзя купить. MAF стандартизирован — AI реально применим.
- **Риск — Сроки:** Q4 2026 нереалистичен при 6/1 графике. 4 зимних месяца = ~350 часов кода — мало для SaaS с агентами и интеграциями. Нужно: радикальное сужение MVP или делегирование кодинга.
- **Риск — AI-блокировки:** Зависимость от заблокированных сервисов через VPN — экзистенциальный риск. Митигация: Venice AI через A0T стейкинг (S3).
- **Риск — Рынок:** "Нет конкурентов" может означать "нет рынка". Нужна валидация: предъявить счёт реальному клиенту до полной разработки.
- **Контр-тезис (IN-3):** Кодинг — навык, который можно купить. Доменная экспертиза и продажи — нельзя. Фокус может быть инвертирован.

### I1: Партнёрство с руководителями фирмы через AI-проекты
**Категория:** Карьера / Бизнес
**Статус:** Активная подготовка (два проекта в разработке)
**Описание:** Вместо резкого ухода из найма — выход на партнёрские отношения с руководством текущей строительной фирмы. Стратегия: подготовить два проекта для созвона/презентации руководителям:
1. **Цифровой Прораб (PWA)** — решение узкого места коммуникации прораб↔офис. Показать как приложение устраняет потерю чеков, рутинные созвоны и путаницу в объёмах.
2. **Timber Frame сайт** — продемонстрировать готовое направление МАФ для расширения бизнеса фирмы.
**Эволюция:** Telegram-бот заморожен → заменён PWA приложением (offline-first, полноценный UI для полевых условий).
**Почему интересно:** Встроенный механизм валидации рынка — если фирма принимает приложение, значит проблема реальна. Доступ к реальным строительным данным. Снижение риска перехода к независимости.
**Следующий шаг:** Довести P3 (PWA) и P1 (сайт TF) до презентационного состояния → юридическое закрепление IP → созвон с руководством
**Связано с:** G0 (Цифровой Прораб PWA), G1 (бизнес МАФ), B0 (совмещение найма + проекты), M0 (Независимость), P3, P1

**RedTeam анализ (8 агентов, 2026-02-20):**
- **Сила (IN-8):** Единственный путь с встроенной валидацией рынка до вложения денег. Корпоративный клиент с бюджетом = доказательство product-market fit.
- **КРИТИЧЕСКИЙ РИСК (4/8 агентов):** Конфликт интересов структурно неизбежен. Руководство увидит side-бизнес и либо предложит невыгодное поглощение (70/30), либо начнёт искать замену.
- **Риск — Prisoner's Dilemma (PT-3):** Демонстрация бота = раскрытие козырей до переговоров. Компания адаптируется первой.
- **Риск — IP (AR-5):** Российское корпоративное право слабо защищает создателя. Если бот создан "в рамках партнёрства", компания претендует на IP.
- **Митигация:** Юридическое закрепление IP с первого дня. Показывать результат, но не процесс. Сохранять информационную асимметрию.

### I2: МАФ как расширение направления благоустройства фирмы
**Категория:** Бизнес / Стратегия
**Статус:** Активная подготовка (сайт TF в разработке)
**Описание:** Текущая фирма расширяется по направлениям благоустройства. МАФ — смежное направление, которое хорошо дополняет благоустройство (конструкции МАФ = часть благоустройства). Стратегия: запустить Timber Frame сайт (P1) как свой параллельный проект для будущих расширений фирмы. На первых этапах — коллаборация с фирмой, позже — собственное направление.
**Почему интересно:** Синергия — фирма получает новое направление, Ivan получает опыт и клиентскую базу. МАФ органично дополняет благоустройство. Сайт TF демонстрирует готовность и компетенцию.
**Следующий шаг:** MVP сайта TF (P1) → презентация руководству совместно с P3 → разграничение IP и зон ответственности
**Связано с:** G1 (бизнес МАФ), B0 (совмещение найма + проекты), B5 (вечные ниши), P1, S6

**RedTeam анализ (8 агентов, 2026-02-20):**
- **Сила (AR-5):** MAF-структура переносима на смежные ниши (благоустройство, стройматериалы, озеленение) без переписывания — только смена датасета. Каждый успех = бесплатный proof-of-concept для следующей ниши.
- **Сила (AR-4):** Вертикальная интеграция "знание ниши + демо + платформа" — классическая точка входа, которую внешний конкурент не скопирует.
- **КРИТИЧЕСКИЙ РИСК:** Одновременное партнёрство и конкурирующий бизнес не могут сосуществовать без юридического разграничения IP с первого дня.
- **Каскадный риск (AR-5):** Доверие → совместный продукт → конкуренция → суд или потеря 1-2 лет работы.

### I3: AI Agent Orchestra — масштабирование на все проекты
**Категория:** Инфраструктура / Продуктивность
**Статус:** Активна (полная интеграция завершена 2026-03-03)
**Описание:** Модель "один человек = команда AI-агентов", применённая ко всем проектам. Navi (архитектор, sync) + Jules (async-исполнитель, 100 задач/день на Pro) + Agent Zero (автономный исследователь) работают параллельно на 14 репозиториях. Jules handles рутину (тесты, баги, TODO, dependencies, security scans), Navi — архитектуру и сложные решения, Agent Zero — глубокие исследования.
**Почему интересно:** Качественный переход от линейной работы к параллельной. Один человек с тремя AI-агентами производит как команда из 3-4 разработчиков. Применимо ко всем проектам: G0 (Цифровой Прораб), G1 (Timber Frame сайт), G2 (Construction Orchestrator), G10/G11 (PAI community).
**Уже работает:**
- Jules подключён к PAI-personal (private), proactive scan включён
- AGENTS.md создан, JulesAPI.ts skill для программного управления
- Agent Zero подключён через REST API (`AgentZero.ts`). 24/7 на VPS, claude-sonnet-4-6, 9 навыков (вкл. TELOS + TheAlgorithm). MCP SSE сконфигурирован (ждёт включения в A0 UI)
- Первый pipeline: Jules нашёл 4 security-уязвимости → Navi отревьюил → применил → 0 кликов от Ivan
- Scheduled Tasks доступны для автоматического maintenance
- **Gemini CLI v0.31.0** — установлен как inference provider в PAI. `bun Inference.ts --level gemini`. Navi вызывает программно (второе мнение, cross-check, Google-знания). Прокси через Амстердам.
- **Z.AI GLM-5** — 5-й inference provider. `bun Inference.ts --level glm5`. 744B MoE, OpenAI-compatible API, прямой доступ из РФ. Coding plan subscription. zai-cli v1.1.0 — MCP tools (vision, search, read, repo) как CLI и MCP server (Vision) в Claude Code.
- **Jules extension** для Gemini CLI — MCP сервер для управления Jules из CLI
- **18 хуков → Jules**: 3 батча тестов делегированы (6+6+6), Jules генерирует
- **Hook perf optimized**: SecurityValidator 282→26ms, UpdateTabTitle 10s→<500ms (−33с/сессию)
- **Events rotation**: архивация >7 дней, 10 тестов, интегрировано в SessionStart
**Следующие шаги:**
- Подключить Jules к другим репо (digital-foreman-app, timber-frame-site)
- Настроить GitHub Actions для auto-fix CI failures
- Deeper Gemini integration: MCP server, автоматический выбор провайдера по задаче
- Jules для community PR в upstream PAI (main branch)
- Z.AI deeper integration: автоматический routing (cheap bulk → GLM-5, critical → Opus), Anthropic-compatible endpoint как запасной (api.z.ai/api/anthropic)
**Связано с:** S1 (AI-автоматизация), MO9 (Agent Orchestra), M0 (независимость — работать как команда), M3 (два AI-провайдера = суверенитет)

## Сводка RedTeam: Три хирургических исправления

Все три идеи связаны и создают воронку. Но для работы нужны три исправления:

1. **Юридическая защита IP** — до любых демонстраций фирме. Закрепить права на бот и платформу как личную собственность.
2. **Сужение фокуса** — один основной трек вместо трёх параллельных. Один человек = одна голова. Рекомендация: I1 (валидация через фирму) первым, I0 (SaaS) вторым, I2 (расширение) третьим.
3. **Делегирование кодинга** — фокус на доменной экспертизе и продажах (нельзя купить), а не на коде (можно купить/делегировать AI).

### I4: Pi Agent как T1 RPC-кодер (межсезонье 2026)
**Категория:** Инфраструктура / Brigade
**Статус:** Идея (отложено до межсезонья, декабрь 2026)
**Описание:** Pi Agent (@mariozechner/pi-coding-agent) — TypeScript coding agent с уникальным RPC-режимом (persistent session, инкрементальные команды, сохранение контекста между вызовами). В отличие от OpenCode CLI (stateless cold start), Pi Agent поддерживает живую сессию. Мульти-провайдер: можно посадить на дешёвые модели (Gemini Flash, DeepSeek) для рутинного кодинга — экономия 10-50x.
**Почему отложено:**
- Текущая бригада не раскрыта на полную — сначала максимизировать потенциал Navi + Jules + A0 + OpenCode
- Сезон 6/1 (апрель-ноябрь) — время-дефицит, интеграция = 4-8 часов вечеров
- A0 масштабируется горизонтально (доп. контейнеры на VPS) если нужна мощность
- Принцип #7: один фокус, не распыляться
**Условия для реализации (из Council Debate 2026-03-06):**
1. Docker-изоляция обязательна (hot-reload расширений = RCE-вектор без контейнера)
2. `--network=none` + explicit volume mounts (WSL2 /mnt/c ломает изоляцию)
3. Конкретный use case, который текущая бригада НЕ закрывает
4. Максимум 8 часов на интеграцию, иначе откладываем
**NanoClaw — отклонён:** Дублирует A0 (scheduled tasks, code execution, subordinates). Anthropic SDK lock-in противоречит M3. Проекту 5 недель, 246 open issues — нестабилен. Возможная роль как security wrapper для Pi Agent — ревизия через 6 месяцев.
**Исследование:** `MEMORY/RESEARCH/2026-03/open-source-ai-agents-research.md` (полный анализ Pi Agent, OpenClaw, NanoClaw)
**Council Debate:** 4 агента (Architect, Engineer, Researcher, Security), 3 раунда. Консенсус: Pi Agent — условно да (межсезонье), NanoClaw — нет.
**Связано с:** S1 (AI-автоматизация), M0 (экономия через дешёвые модели), M3 (мульти-провайдер = суверенитет), I3 (AI Agent Orchestra)
