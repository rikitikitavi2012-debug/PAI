# PAI Memory Guidance

Дисциплина работы с MEMORY — что, когда и как сохранять. На основе паттерна из Hermes Agent.

---

## Принцип

> **Сохраняй то, что избавит Ivan от будущего исправления или уточнения.**

Лучшая память — та, которая предотвращает повторение. Не "всё подряд", а "то, что уменьшает friction".

---

## Что сохранять

### ✅ Сохраняй

| Категория | Примеры |
|-----------|---------|
| **User preferences** | Формат ответов (терсиый), язык (русский), emoji (только если попросил) |
| **Tool quirks** | "Jules медленный — batch через скрипт", "A0 не отвечает — poll не спамь" |
| **Context constraints** | Сезон 6/1 (апрель-ноябрь), бюджет ограничен, соло-предприниматель |
| **Stable conventions** | Upstream strategy (cherry-pick only), cross-model review для Algorithm |
| **Bug patterns** | "JS \b не матчит кириллицу — use (?:^\|^s)" |
| **Workflow preferences** | MVP first, /simplify после нового кода, parallel agents для 3+ задач |

### ❌ НЕ сохраняй

| Категория | Почему |
|-----------|--------|
| **Код паттерны** | Видны из кода, дублирование |
| **Git history** | `git log` авторитетен |
| **Debug рецепты** | Фикс в коде, коммит объясняет |
| **Эфемерное** | Текущая задача, временные state |
| **Уже в CLAUDE.md** | Не дублировать |

---

## Когда сохранять

### Триггеры

1. **Ivan исправил меня** → сохранить correction
2. **Ivan подтвердил неочевидный подход** → сохранить как validated decision
3. **Повторяющийся вопрос** → сохранить факт, чтобы не спрашивать снова
4. **Квирк инструмента** → сохранить сразу после обнаружения
5. **Завершённый цикл** → LEARN фаза → MEMORY update

### Частота

- **Не чаще 1-2 записей за сессию** — память должна быть compact
- **Не в середине задачи** — батчить в LEARN фазу
- **Не дублировать** — сначала проверить MEMORY.md

---

## Как сохранять

### Структура записи

```markdown
## Feedback
- [Title](file.md) — краткое описание. **Why:** причина. **How to apply:** когда применять.
```

### Body format (для feedback/project типов)

```
Rule/Fact

**Why:** Причина (инцидент, предпочтение, constraint)

**How to apply:** Когда и как применять это правило
```

### Примеры

**Correction:**
```markdown
- [Не спамить A0](feedback_no_spam_a0.md) — не слать повторные запросы A0.
  **Why:** A0 завис от флуда.
  **How to apply:** Ждать ответ или poll с интервалом 30s+.
```

**Validated decision:**
```markdown
- [Parallel agents для 3+ задач](feedback_parallel_agents.md) — spawn agents, не sequential.
  **Why:** 3x speedup на batch операциях.
  **How to apply:** 3+ независимых подзадачи = spawn parallel agents.
```

## Интеграция с Algorithm

Memory Guidance применяется в:
- **LEARN фаза** — после каждого цикла проверить: что стоит сохранить?
- **OBSERVE фаза** — проверить MEMORY на релевантные записи
- **При corrections** — Ivan исправил → сохранить немедленно

---

## Метрика успеха

Хорошая MEMORY система = **меньше повторений**.

Если Ivan говорит "я уже говорил", "напомню ещё раз" → память не работает.
Если PAI применяет past learnings без напоминаний → память работает.
