# Brigade Audit Workflow

Мульти-модельный аудит TELOS и личного кора через AI Brigade.
Три модели сканируют `~/.claude/PAI/USER/` с разных линз, Navi синтезирует и применяет.

## Trigger Phrases

- "audit TELOS", "аудит TELOS"
- "brigade audit", "бригадный аудит"
- "scan TELOS with brigade", "проверь TELOS бригадой"
- "multi-model TELOS review"
- "найди противоречия в TELOS"

## What It Does

1. Запускает 3 модели параллельно (Gemini, Kimi, GLM-5) с разными линзами
2. Каждая модель сканирует весь `~/.claude/PAI/USER/` (TELOS + BUSINESS + DOMAINS + корневые)
3. Navi собирает 3 отчёта, синтезирует, убирает дубли и фантомные находки
4. {PRINCIPAL.NAME} даёт замечания и корректирует
5. Navi применяет изменения через Update workflow

## Prerequisites

- AI Brigade настроена (Gemini CLI, OpenCode CLI, Agent Zero)
- PAI-personal repo актуален (автоматический push в Phase 1)
- Все 3 агента доступны (автоматический health check в Phase 1)

## Phase 1: Подготовка (Navi)

### 1.1 Синхронизация repo для A0

A0 работает через GitHub repo `rikitikitavi2012-debug/PAI-personal`.
Перед запуском убедиться что все изменения запушены:

```bash
# Проверить незакоммиченные изменения в USER/
git status --short PAI/USER/ | head -20

# Если есть — закоммитить и запушить
git add PAI/USER/ && git commit -m "chore: sync USER core before brigade audit"
git push private master
```

**КРИТИЧНО:** Без этого A0 будет анализировать устаревшую версию.

### 1.2 Health Check бригады

Запускать **параллельно** (3 команды одновременно):

```bash
# A0 — должен ответить "✅ Agent Zero is running"
bun ~/.claude/PAI/Tools/AgentZero.ts health

# Gemini CLI — любой короткий ответ = ОК
echo "OK" | gemini -p "" -y -o text --include-directories ~/.claude/PAI/USER/ 2>&1 | tail -3

# OpenCode CLI — любой ответ = ОК
opencode run "OK" 2>&1 | tail -3
```

**Если агент не отвечает:**
- A0: проверить `curl http://72.56.86.51:50002/` — может быть перезапуск контейнера
- Gemini: проверить `GOOGLE_API_KEY` в `~/.config/PAI/.env` и прокси (`_ensure_proxy`)
- OpenCode: проверить `opencode` binary (`which opencode`) и конфиг (`~/.config/opencode/opencode.json`)

**Fallback:** Если один агент недоступен — запускать двумя. Аудит двумя моделями лучше чем никакого.

## Phase 2: Запуск бригады (параллельно)

Запускать все 3 команды **одновременно в фоне** (`run_in_background: true`).

### 2.1 Gemini CLI — Линза: ПРОТИВОРЕЧИЯ И СВЯЗИ

**Модель:** Gemini 2.5 Pro (1M контекст — все файлы влезут)
**Сила:** Длинный контекст, видит связи между далёкими файлами

```bash
echo 'Ты аудитор личной системы TELOS. Просканируй ВСЮ директорию ~/.claude/PAI/USER/ (она уже включена через --include-directories).

ЗАДАЧА: Найди ПРОТИВОРЕЧИЯ и РАЗОРВАННЫЕ СВЯЗИ.

Что искать:
1. ПРОТИВОРЕЧИЯ: Конфликты между BELIEFS↔GOALS, MISSION↔PROJECTS, STRATEGIES↔текущий STATUS
2. РАЗОРВАННЫЕ ЦЕПОЧКИ: Цели без стратегий, стратегии без проектов, проблемы без решений
3. КОНФЛИКТ ПРИОРИТЕТОВ: TELOS говорит одно, PROJECTS делает другое
4. БИЗНЕС vs ЛИЧНОЕ: Несогласованность BUSINESS/ с TELOS/GOALS
5. DOMAINS/CONSTRUCTION: Экспертиза не отражённая в целях или стратегиях

Прочитай ВСЕ файлы в директории USER/. Особенно важны:
- TELOS/ - все файлы (GOALS, MISSION, BELIEFS, STRATEGIES, STATUS, PROBLEMS, IDEAS, PROJECTS и т.д.)
- BUSINESS/ - бренд и компания
- DOMAINS/CONSTRUCTION/ - экспертиза
- Корневые файлы: ABOUTME, OPINIONS, RESUME

Формат ответа строго JSON:
{
  "contradictions": [{"file1": "...", "file2": "...", "description": "...", "severity": "high|medium|low"}],
  "broken_chains": [{"from": "...", "missing_link": "...", "description": "..."}],
  "priority_conflicts": [{"stated": "...", "actual": "...", "description": "..."}],
  "hidden_strengths": [{"area": "...", "description": "..."}],
  "summary": "3-5 предложений общей оценки системы"
}' | gemini -p "" -y -o text --include-directories ~/.claude/PAI/USER/ 2>&1
```

**Таймаут:** до 5 минут (Gemini может думать долго на 200+ файлах).

### 2.2 OpenCode / Kimi K2.5 — Линза: ПРОБЕЛЫ И УПУЩЕННОЕ

**Модель:** Kimi K2.5 (128K контекст)
**Сила:** "Здравый смысл", видит что упущено

```bash
opencode run --dir ~/.claude/PAI/USER 'Ты аудитор личной системы жизненного планирования. Перед тобой директория USER/ — это личный кор человека: цели, миссия, убеждения, бизнес, экспертиза в строительстве.

ЗАДАЧА: Найди ПРОБЕЛЫ и УПУЩЕННЫЕ ВОЗМОЖНОСТИ.

Прочитай все файлы в текущей директории и поддиректориях. Особенно:
- TELOS/ - цели, миссия, убеждения, стратегии, проблемы, идеи
- BUSINESS/ - бренд, компания
- DOMAINS/CONSTRUCTION/ - экспертиза (каркас, благоустройство)
- Корневые: ABOUTME.md, OPINIONS.md, RESUME.md, TECHSTACKPREFERENCES.md

Что искать:
1. ПРОБЕЛЫ: Области жизни без целей (здоровье? отношения? финансы? образование?)
2. МЁРТВЫЕ ЗАПИСИ: Устаревшие цели, неактуальные стратегии, забытые проекты
3. УПУЩЕННЫЕ МИССИИ: Что напрашивается из контекста но не артикулировано
4. СКРЫТЫЕ ПАТТЕРНЫ: Повторяющиеся темы через разные файлы
5. НЕЗАКРЫТЫЕ ПЕТЛИ: Проблемы без стратегий, идеи без проектов
6. ЭКСПЕРТИЗА→БИЗНЕС: Знания в DOMAINS/ не монетизированные через BUSINESS/

Формат ответа строго JSON:
{
  "gaps": [{"area": "...", "description": "...", "suggestion": "..."}],
  "dead_entries": [{"file": "...", "entry": "...", "reason": "..."}],
  "missing_missions": [{"theme": "...", "evidence": "...", "proposed": "..."}],
  "hidden_patterns": [{"pattern": "...", "found_in": ["file1", "file2"], "insight": "..."}],
  "unclosed_loops": [{"start": "...", "missing": "...", "suggestion": "..."}],
  "summary": "3-5 предложений общей оценки"
}' 2>&1
```

**Таймаут:** до 5 минут.

### 2.3 Agent Zero / GLM-5 — Линза: ВНЕШНИЙ ВЗГЛЯД

**Модель:** GLM-5 (200K контекст) + browser_agent + code_execution_tool
**Сила:** Свежий взгляд через repo, не видит локальный контекст — оценивает как сторонний консультант

**ВАЖНО — особенности A0:**
- A0 выполняет задачу в 30-50+ шагов (клонирование repo, чтение файлов, анализ)
- Используй **sync** режим (`message`) — он ждёт до 10 минут
- **НЕ СПАМИТЬ** повторные запросы — A0 уже работает. Один запрос, одно ожидание
- Если sync таймаутнул — A0 всё равно работает. Подождать и проверить через `poll`
- **НЕ отправлять async повторно** — это создаст второй параллельный чат

```bash
bun ~/.claude/PAI/Tools/AgentZero.ts message 'Проведи глубокий аудит моего личного кора. Репозиторий: https://github.com/rikitikitavi2012-debug/PAI-personal — клонируй его и просканируй директорию PAI/USER/ целиком.

ЗАДАЧА: ВНЕШНИЙ ВЗГЛЯД — оценка как сторонний консультант.

Что искать:
1. КОГЕРЕНТНОСТЬ: Насколько система целостна? Все части работают вместе или разрозненны?
2. РЕАЛИСТИЧНОСТЬ: Цели достижимы для соло-предпринимателя с графиком 6/1 в строительный сезон (апрель-ноябрь)?
3. УПУЩЕННЫЕ ИДЕИ: Что очевидно снаружи но не видно изнутри?
4. ВРЕМЕННАЯ АКТУАЛЬНОСТЬ: Что устарело? Что нужно обновить?
5. СИЛА СИСТЕМЫ: Что реально сильно и стоит развивать дальше?
6. РЕКОМЕНДАЦИИ: Топ-5 конкретных действий для усиления системы

Просканируй ВСЕ файлы в PAI/USER/:
- TELOS/ - жизненная система (цели, миссия, убеждения, стратегии)
- BUSINESS/ - бизнес контекст
- DOMAINS/CONSTRUCTION/ - профессиональная экспертиза
- Корневые файлы - идентичность и предпочтения

Верни структурированный отчёт с секциями по каждому пункту и числовыми оценками 1-10.' 2>&1
```

**Таймаут:** до 10 минут. A0 медленный — это нормально.

### Если A0 таймаутнул (exit code 1, "The operation timed out")

**НЕ ПАНИКОВАТЬ. НЕ ОТПРАВЛЯТЬ ПОВТОРНО.**

A0 уже получил задачу и работает. Проверить:

```bash
# Проверить события — был ли запрос доставлен
tail -5 ~/.claude/MEMORY/STATE/events.jsonl | grep "a0\."

# Поллить результаты (не чаще чем раз в 2 минуты)
bun ~/.claude/PAI/Tools/AgentZero.ts poll
```

Если `a0.message_sent` есть в events — задача доставлена. Ждать.
Спросить {PRINCIPAL.NAME}: "A0 ещё работает?" — он может видеть прогресс в A0 Web UI.

## Phase 3: Сбор результатов

### 3.1 Порядок получения

Результаты приходят в произвольном порядке (обычно: OpenCode первый, Gemini второй, A0 последний).
По мере получения каждого — кратко сообщать {PRINCIPAL.NAME} ключевые находки.

### 3.2 Обработка результатов

Для каждого отчёта:
1. Проверить что ответ содержит структурированные данные (JSON или разделы)
2. Если модель вернула текст вместо JSON — извлечь ключевые находки вручную
3. Сохранить сырой ответ (для аудит-трейла)

### 3.3 Если агент не ответил

| Ситуация | Действие |
|----------|----------|
| Gemini молчит >5 мин | Проверить task output. Если пусто — пересоздать запрос |
| OpenCode молчит >5 мин | Проверить `opencode run` процесс. Перезапустить если нужно |
| A0 молчит >10 мин | НЕ пересоздавать. Спросить {PRINCIPAL.NAME} — он видит A0 UI |
| 2 из 3 ответили | Начинать синтез. A0 добавить позже |

## Phase 4: Синтез (Navi)

### 4.1 Таблица консенсуса

Построить таблицу: какие находки подтверждены несколькими моделями.

```markdown
| # | Находка | Gemini | Kimi | A0 | Confidence |
|---|---------|--------|------|----|------------|
| 1 | [описание] | ✅ | ✅ | ✅ | CONFIRMED (3/3) |
| 2 | [описание] | ✅ | ✅ | — | HIGH (2/3) |
| 3 | [описание] | ✅ | — | — | MEDIUM (1/3) |
```

**Правило:** 3/3 = действовать. 2/3 = обсудить. 1/3 = отметить для справки.

### 4.2 Фильтр фантомных находок

Модели могут генерировать "фантомные" противоречия — вещи которые выглядят как конфликт,
но на самом деле осознанный трейд-офф {PRINCIPAL.NAME}. Примеры:
- "W5 один фокус vs 3 проекта" — может быть осознанный pipeline (W5 Override)
- "Нет стратегии X" — может быть осознанно отложено

**Финальный фильтр — ВСЕГДА {PRINCIPAL.NAME}.**

### 4.3 Категоризация

Разделить находки на:
1. **Противоречия** — конфликты между файлами
2. **Пробелы** — области без целей/стратегий
3. **Мёртвые записи** — устаревшее для чистки
4. **Скрытые паттерны** — глубинные инсайты
5. **Скрытые силы** — что развивать
6. **Топ действий** — приоритизированный список

### 4.4 Итоговые оценки


## Phase 6: Применение изменений (Navi)

На основе одобренных находок:

### 6.1 Обновление TELOS файлов

**Перед любыми правками — бэкап:**
```bash
BACKUP_TS=$(date +%Y%m%d-%H%M%S)
cd ~/.claude/PAI/USER/TELOS
for f in GOALS.md STRATEGIES.md MISSION.md STATUS.md PROJECTS.md TRAUMAS.md; do
  cp "$f" "Backups/${f%.md}-${BACKUP_TS}.md"
done
```

Затем — хирургические правки через Edit tool:
- Новые цели (G#) → GOALS.md
- Новые стратегии (S#) → STRATEGIES.md
- Обновление статусов → STATUS.md
- Чистка мёртвых записей → соответствующие файлы
- Заполнение пустых шаблонов → TRAUMAS.md и т.д.

### 6.2 Логирование в updates.md

Добавить запись в начало `~/.claude/PAI/USER/TELOS/updates.md`:
```markdown
## YYYY-MM-DD — Мульти-модельный аудит TELOS (Gemini + Kimi + GLM-5/A0)

**Метод:** 3 модели, параллельный запуск, синтез Navi
**Находки:** X подтверждённых, Y уникальных
**Изменения:** [список файлов и что изменено]
**Замечания {PRINCIPAL.NAME}:** [что отложено/скорректировано]
**Бэкапы:** Backups/*-{TIMESTAMP}.md
```

### 6.3 Сохранение аудита в MEMORY

```bash
# Полный отчёт для будущих сравнений
~/.claude/MEMORY/RESEARCH/YYYY-MM/telos-brigade-audit.md
```

### 6.4 Коммит

```bash
git add PAI/USER/ MEMORY/RESEARCH/
git commit -m "feat(TELOS): brigade audit — [краткое описание ключевых изменений]"
git push private master  # синхронизация для A0
```

## Lessons Learned (из ручного запуска 2026-03-13)

| Урок | Детали |
|------|--------|
| **A0 медленный — это нормально** | 50+ шагов, 5-10 минут. НЕ спамить повторные запросы |
| **Один запрос — одно ожидание** | Повторный async создаёт второй чат, путает A0 |
| **Git push перед A0** | A0 работает через repo, не локально |
| **Gemini CLI тормозит на health check** | Может думать 30с+ на простом "OK". Не ждать — сразу запускать основной запрос |
| **JSON формат дисциплинирует модели** | Без него — эссе. С JSON — структурированные данные для синтеза |
| **Замечания Ivan = часть аудита** | Человек видит контекст которого нет у моделей (дружба с Шульцем, планы на квартиру) |
| **2 из 3 достаточно для синтеза** | Не блокироваться на одном агенте. Начать синтез, добавить позже |
| **`--include-directories` для Gemini** | Без этого Gemini не видит файлы USER/ |
| **`--dir` для OpenCode** | Задаёт рабочую директорию, OpenCode видит все файлы |
