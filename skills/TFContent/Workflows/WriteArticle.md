# WriteArticle — Workflow

> Создание экспертных статей для блога timber-frame-spb.ru.
> Каждая статья = SEO-оптимизированный экспертный контент с конкретикой.

---

## Входные данные

| Параметр | Обязательный | Описание |
|----------|-------------|----------|
| Тема/заголовок | ✅ | Заголовок или тема статьи |
| Целевая персона | ✅ | Андрей / Елена / Сергей |
| Длина (слов) | По умолчанию 1200 | 800-2000 слов |
| Ключевые слова | Рекомендуется | 3-5 целевых ключей для SEO |
| CTA | По умолчанию «Калькулятор» | Куда ведём читателя |
| Бриф | Опционально | Дополнительные инструкции из A0_TASK_BRIEF.md |

---

## Шаги выполнения

### Шаг 0: Wordstat Research (ОБЯЗАТЕЛЬНО!)

**Перед написанием любой статьи** выполнить `Workflows/WordstatResearch.md`:

1. Подготовить 3-7 вариаций фраз по теме статьи
2. Запросить Wordstat API (CreateNewWordstatReport → GetWordstatReport → DeleteWordstatReport)
3. Собрать Keyword Brief с частотностями
4. Использовать реальные данные для выбора H1, H2, meta description

**Без Keyword Brief статья не публикуется.** Ключевые слова в плане статьи должны иметь реальные частотности рядом.

### Шаг 1: Загрузка контекста
```
READ ~/.claude/skills/TFContent/TFExpertise.md
READ ~/.claude/skills/TFContent/TFBrandVoice.md
READ (бриф статьи, если указан)
READ (Keyword Brief из Шага 0)
```

### Шаг 2: Планирование структуры

Создать план статьи ПЕРЕД написанием:

```markdown
## План статьи
- **Тема:** [тема]
- **Персона:** [имя] — [что знает/не знает/боится]
- **Ключевые слова (из Wordstat):** [3-5 ключей с частотностями, primary выделен]
- **Структура:**
  1. [H2: подтема] — [что раскрываем, ~X слов]
  2. [H2: подтема] — [что раскрываем, ~X слов]
  3. [H2: подтема] — [что раскрываем, ~X слов]
- **CTA:** [конкретное действие + ссылка]
- **Уникальный угол:** [чем статья отличается от конкурентных]
```

### Шаг 3: Написание

Правила при написании:
1. **Лид (первые 2-3 предложения):** Зацепка через боль или мечту персоны. Ключевое слово в первом абзаце.
2. **Каждый H2:** Содержит хотя бы одну конкретную цифру (цена, размер, срок, характеристика).
3. **Таблицы:** Использовать для сравнений (наше vs обычное, материал A vs B).
4. **Внутренние ссылки:** Минимум 2-3 ссылки на другие страницы сайта.
5. **Финал:** CTA с конкретным действием, не абстрактный «свяжитесь с нами».
6. **IMAGE-плейсхолдеры (ОБЯЗАТЕЛЬНО):** Вставить 3-5 плейсхолдеров для изображений. Формат:
   ```
   <!-- IMAGE: slot=N, type=header|detail|comparison|atmosphere, description="описание сцены", seo_alt="ключ из Wordstat — описание", keyword="целевой ключ", position="after_h1|after_paragraph_N|after_table" -->
   ```
   - slot=1 всегда type=header (заголовочное изображение)
   - seo_alt использует ключевое слово из Wordstat Brief
   - Navi возьмёт плейсхолдеры и сгенерирует визуалы через бригаду (см. IllustratedArticle.md)

### Шаг 4: Самопроверка по Quality Gates

Пройтись по каждому гейту из SKILL.md:

```markdown
## Проверка
- [ ] Gate 1 Brand Voice: нет запрещённых фраз, есть конкретика
- [ ] Gate 2 Technical: материалы/цены/нормы верны
- [ ] Gate 3 SEO: ключевые слова в H1/H2, meta description готов
- [ ] Gate 4 Persona: страхи адресованы, CTA для нужной стадии
```

### Шаг 4.5: Валидация ссылок и путей

Проверить ВСЕ ссылки и пути в статье:

1. **Внутренние ссылки — только латиница.** Никакой кириллицы в URL (например `/kalkulyатор` — ОШИБКА).
2. **Допустимые внутренние ссылки:**
   - `/kalkulyator`, `/tekhnologiya`, `/kontakty`, `/o-nas`
   - `/terrasy/timber-frame`
   - `/blog`, `/blog/{slug}` (slug = латиница, цифры, дефисы)
3. **Пути к изображениям** должны начинаться с `/images/blog/{slug}/` (slug статьи).

Если найдена невалидная ссылка — исправить до перехода к Шагу 5. Статья с кириллическими URL не публикуется.

### Шаг 5: Финальный пакет

Выдать статью в формате:

```markdown
---
title: "[SEO-заголовок]"
description: "[Meta description 150-160 chars]"
slug: "[url-slug]"
persona: "[Андрей|Елена|Сергей]"
keywords: ["ключ1", "ключ2", "ключ3"]
cta: "[тип CTA]"
word_count: [число]
image_slots: [число плейсхолдеров]
---

# [H1]

[Тело статьи...]
```

Сохранить в `docs/content/blog/[slug].md`

### Статья 1: «Что такое Timber Frame?»
- **Файл:** `chto-takoe-timber-frame.md`
- **Персона:** Елена (не знает TF)
- **Длина:** 1500 слов
- **Угол:** Альпийские шале → видимый каркас → красота + надёжность
- **Ключи:** что такое timber frame, фахверк терраса, timber frame технология
- **CTA:** Калькулятор стоимости
- **Структура:**
  1. Что такое Timber Frame простым языком (аналогия с шале)
  2. Как это работает: каркас, соединения, материалы
  3. TF vs обычный каркасник: 5 конкретных отличий (таблица)
  4. Почему TF подходит для террас (видимый каркас = дизайн)
  5. Сколько стоит и как заказать (CTA → калькулятор)

### Статья 2: «Дерево в климате СПб — почему надёжно»
- **Файл:** `derevo-v-klimate-spb.md`
- **Персона:** Елена + Сергей (боятся гниения)
- **Длина:** 1200 слов
- **Угол:** Лиственница = природная защита, клеёный брус = стабильность
- **Ключи:** лиственница свойства, дерево терраса долговечность, климат Петербурга дерево
- **CTA:** Посмотреть наши объекты
- **Структура:**
  1. «Дерево сгниёт!» — главный миф (и почему он неверен)
  2. Лиственница: цифры, которые убеждают (плотность, танины, Венеция)
  3. Клеёный брус: почему не ведёт и не трескается
  4. Защита: Osmo, Teknos, Remmers — что реально работает
  5. 5 правил долговечной деревянной террасы в СПб

### Статья 3: «TF vs обычная терраса: стоимость за 10 лет»
- **Файл:** `terrasa-vs-obychnaya-10-let.md`
- **Персона:** Сергей (цена) + Елена (обосновать мужу)
- **Длина:** 1000 слов
- **Угол:** TCO (Total Cost of Ownership) — считаем честно
- **Ключи:** стоимость владения терраса, сравнение террас, фахверк терраса цена
- **CTA:** Рассчитать в калькуляторе
- **Структура:**
  1. Две террасы: обычная 400К vs TF 750К (стартовая цена)
  2. Скрытые расходы обычной: ремонт каждые 3-4 года (таблица по годам)
  3. TF через 10 лет: только обновление покрытия (15К × 2 = 30К)
  4. Итоговая таблица: обычная 550К/10 лет vs TF 780К/20 лет
  5. Формула: делим на срок службы → TF дешевле за год
