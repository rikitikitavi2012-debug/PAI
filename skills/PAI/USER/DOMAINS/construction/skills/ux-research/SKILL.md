# Skill: UX Research (Информационная архитектура)

## Цель
Определить структуру сайта, навигацию, приоритет контента и логику взаимодействия. Ответить на вопрос: "Что пользователь должен увидеть, в каком порядке, чтобы оставить заявку?"

## Входные данные
- Buyer Personas (docs/research/BUYER_PERSONAS.md)
- Brand Guidelines (docs/research/BRAND_GUIDELINES.md)
- SEO семантическое ядро (SEO_SEMANTIC_CORE.md)
- Анализ сайтов конкурентов (COMPETITOR_WEBSITES.md)
- Прайс-лист работ (PRICE_LIST_WORKS.md)
- Бизнес-процессы (processes/)

## Методология

### 1. Карта сайта (Sitemap)
- Полная структура страниц с иерархией
- Для каждой страницы: URL, title, основной SEO-кластер, приоритет
- Обоснование через Customer Journey из персон

### 2. Приоритет контента на главной
- Порядок секций сверху вниз с обоснованием
- Hero section: что видит пользователь за первые 5 секунд
- Элементы доверия и их расположение
- CTA: формулировки и расположение

### 3. Wireframes (текстовое описание)
Для каждой ключевой страницы (главная, каталог, услуга, портфолио, калькулятор, о компании, контакты):
- Цель страницы
- Секции сверху вниз с содержимым
- CTA формулировки
- Какую персону обслуживает
- Этап Customer Journey

### 4. Навигация
- Основное меню (desktop + mobile)
- Footer навигация
- Хлебные крошки
- Внутренняя перелинковка

### 5. Конверсионные элементы
- Формы: поля и минимум для каждого этапа воронки
- Калькулятор: параметры ввода, формат вывода
- Триггеры доверия (отзывы, гарантии, портфолио)
- Social proof
- Urgency/scarcity: уместность и применение

### 6. Mobile-first
- Изменения контента на мобильном
- Приоритет контента
- Жесты (свайпы галерей)
- Критичные элементы для скорости

### 7. Accessibility
- Контрастность, размер кликабельных элементов
- Alt-тексты, навигация с клавиатуры

## Формат выхода
Markdown-файл `UX_RESEARCH.md` со всеми 7 разделами.

## Критерии качества
- [ ] Все 7 разделов присутствуют
- [ ] Каждая страница в Sitemap привязана к SEO-кластеру
- [ ] Wireframes содержат конкретные секции, не абстрактные описания
- [ ] Калькулятор детально проработан (параметры, логика, UI)
- [ ] Решения обоснованы через персоны (не "хорошо бы", а "Персона А нуждается")
- [ ] Mobile-версия — не "уменьшенный десктоп", а отдельная проработка
- [ ] Каждый CTA имеет конкретную формулировку и привязку к этапу воронки
