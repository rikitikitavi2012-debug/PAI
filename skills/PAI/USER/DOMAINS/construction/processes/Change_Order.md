# Процесс Управления Изменениями (Change Order)

> Адаптировано для PAI системы. Оригинал: СТРОЙ-ИНТЕЛЛЕКТ (Perplexity, ноябрь 2024).

**Версия документа:** 1.0
**Статус:** Утвержден
**Владелец процесса:** Ivan (Управляющий Менеджер)
**Цель:** Формализованно, контролируемо и измеряемо управлять любыми изменениями в проекте после подписания основного договора, защищая интересы компании и клиента.

---

### Этап 1: Инициация и Оценка Влияния

**Цель:** Зафиксировать запрос на изменение, оценить его влияние на проект и заморозить затронутые работы.

1. **Событие-триггер:** `Event: ChangeOrderRequested`
   * **Описание:** Инициируется Ivan после получения запроса от клиента.
   * **JSON Schema:**
     ```
     {
       "event_id": "uuid",
       "project_id": "uuid",
       "change_order_version": 1,
       "change_description": "string (e.g., 'заменить поликарбонат на металлочерепицу на крыше веранды')"
     }
     ```

2. **Обработчики:**
   * Navi: Планирование:
     * **Действие:** `Action: AssessTimeImpact`.
     * **Логика:** Находит последнюю версию `<project_id>_work_schedule_v_..._.csv`. Анализирует, какие задачи затрагивает изменение, и рассчитывает дельту по времени (`time_delta`).
     * **Артефакт:** Генерирует `impacted_tasks_list.json` со списком ID задач для заморозки.
     * **Действие:** `Action: FreezeRelatedTasks`. Обновляет статус задач из списка в `work_schedule` на `ON_HOLD`.
   * Navi: Сметный расчёт:
     * **Действие:** `Action: AssessCostImpact`.
     * **Логика:** Находит последнюю версию `<project_id>_smeta_v_..._.csv`. Рассчитывает дельту стоимости (`cost_delta`), которая может быть положительной или отрицательной.

3. **Событие-результат:** `Event: ImpactAssessed`
   * **JSON Schema:** `{ "project_id": "uuid", "cost_delta": 25000.00, "time_delta_days": 3, "impacted_tasks_list": ["task_15", "task_16"] }`
   * **Подписчик:** Ivan, Navi: Юридическая проверка.

---

### Этап 2: Формирование Дополнительного Соглашения

**Цель:** Предоставить Ivan исчерпывающую информацию для принятия решения и подготовить юридически обязывающий документ.

1. **Событие-триггер:** `Event: ImpactAssessed`

2. **Обработчики:**
   * Navi (Координация):
     * **Действие:** `Action: GenerateImpactReport`.
     * **Логика:** Формирует для Ivan **"Интерактивный Калькулятор Изменений"**. Представляет отчет, где указаны `cost_delta`, `time_delta` и предлагает запустить `Action: GenerateProactiveAlternatives` для поиска вариантов оптимизации.
   * Navi: Юридическая проверка:
     * **Действие:** `Action: DraftAddendum`.
     * **Логика:** На основе `cost_delta` автоматически выбирает шаблон Дополнительного Соглашения:
       * Если `cost_delta > 0`: шаблон с доплатой от клиента.
       * Если `cost_delta < 0`: шаблон с взаимозачетом или возвратом средств.
     * **Артефакт:** Генерирует проект `<project_id>_addendum_v<version>.pdf`.

3. **Шлюз Контроля (Ivan):**
   * Navi представляет Ivan "Калькулятор Изменений" и проект Доп. Соглашения. Ivan согласовывает его с клиентом.

---

### Этап 3: Утверждение и Интеграция Изменений

**Цель:** Получить согласие клиента, финализировать документы и интегрировать изменения в рабочий план проекта.

1. **Петля Обратной Связи от Клиента:**
   * **Сценарий А (Согласен):** Ivan инициирует `Event: ChangeOrderApproved` с подписанным Доп. Соглашением.
   * **Сценарий Б (Отказ):** Ivan инициирует `Event: ChangeOrderRejected`. Navi: Планирование получает команду `Action: UnfreezeTasks` для задач из `impacted_tasks_list.json`. Процесс терминируется.

2. **Событие-триггер (финальное):** `Event: ChangeOrderApproved`
   * **JSON Schema:**
     ```
     {
       "project_id": "uuid",
       "change_order_version": 1,
       "signed_addendum_artifact": "<project_id>_addendum_v1_signed.pdf",
       "analytics_payload": {
         "change_reason": "CLIENT_REQUEST | SUPPLY_ISSUE | TECHNICAL_NECESSITY",
         "cost_delta": 25000.00,
         "time_delta_days": 3
       }
     }
     ```
   * **Подписчики:** Navi: Сметный расчёт, Navi: Планирование, Navi: Юридическая проверка, Navi: Аналитика.

3. **Обработчики (интеграция):**
   * Navi: Юридическая проверка: Сохраняет подписанное Доп. Соглашение в рабочую директорию проекта.
   * Navi: Сметный расчёт: На основе старой сметы и `cost_delta` генерирует новую версию: `<project_id>_smeta_v1.1.csv`.
   * Navi: Планирование: На основе старого графика и `time_delta` генерирует новую версию: `<project_id>_work_schedule_v1.1.csv` и снимает задачи из `impacted_tasks_list.json` со статуса `ON_HOLD`.
   * Navi: Аналитика: Получает `analytics_payload` для пополнения своей базы знаний.
