# Предпочения алгоритма (Algorithm Preferences)

**Настройте, как работает THE ALGORITHM для вас.**

THE ALGORITHM — это универсальный движок выполнения PAI: **Текущее состояние → Идеальное состояние** через верифицируемую итерацию. Этот файл настраивает то, как он работает для ваших конкретных потребностей.
---

## Предпочения верификации (Verification Preferences)

### Насколько полной должна быть верификация?

- [ ] **Quick (Быстрая)** — Базовые проверки, доверять общим паттернам
- [ ] **Standard (Стандартная)** — Верифицировать ключевые утверждения, выборочно проверять детали
- [x] **Thorough (Тщательная)** — Верифицировать все, несколько проходов валидации

### Методы верификации
Предпочитаемые подходы верификации:
- [x] Автоматические тесты, когда доступны
- [x] Ручные выборочные проверки для UI/UX
- [x] Проверка через браузер для веб-изменений
- [ ] Требовать скриншоты для визуальных изменений

---

## Стиль итерации (Iteration Style)

### Скорость итерации
- [ ] **Fast (Быстрая)** — Делать несколько изменений за итерацию
- [x] **Standard (Стандартная)** — Одно логическое изменение за итерацию
- [ ] **Careful (Осторожная)** — Только небольшие инкрементальные изменения

### Когда останавливаться
Остановиться и спросить перед:
- [x] Разрушительными изменениями
- [x] Деплоями в production
- [x] Миграциями базы данных
- [x] Изменениями, чувствительными к безопасности
- [ ] Любым удалением файлов

---

## Подход к решению проблем (Problem-Solving Approach)

### Когда планировать, а когда выполнять
- **Простые задачи** (< 3 шагов): Выполнять напрямую
- **Средние задачи** (3-10 шагов): Краткий план, затем выполнение
- **Сложные задачи** (> 10 шагов): Детальный план, получить одобрение

### Исследование против действия
- [x] **Research-first (Исследование сначала)** — Исследовать тщательно перед действием
- [ ] **Balanced (Сбалансированный)** — Быстрое исследование, затем итеративное действие
- [ ] **Action-first (Действие сначала)** — Пробовать, корректировать на основе результатов

## Пороги качества (Quality Thresholds)

### Приемлемые уровни качества
| Контекст | Минимальное качество |
|---------|-----------------|
| Production code (Код для production) | Высокое (протестирован, проверен) |
| Прототипы | Среднее (функционально) |
| Скрипты/инструменты | Среднее (работает) |
| Документация | Высокое (точно, четко) |

### Определение "Готово"
Задача завершена, когда:
- [x] Основная функционала работает
- [x] Краевые случаи обработаны
- [x] Тесты проходят (если применимо)
- [x] Не введено регрессии
- [x] Документация обновлена
- [x] Код проверен (code review)

## Общение во время выполнения (Communication During Execution)

### Обновления прогресса
- [ ] **Minimal (Минимальные)** — Отчитываться только о завершении
- [x] **Standard (Стандартные)** — Отчитываться на основных этапах
- [ ] **Verbose (Многословные)** — Отчитываться о каждом шаге

### Когда что-то идет не так
- [x] Объяснить, что произошло
- [x] Предложить решения
- [x] Спросить перед основными действиями по восстановлению
- [ ] Сначала пытаться автовосстановление
