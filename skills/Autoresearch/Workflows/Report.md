# Report Workflow

**Назначение:** Генерация аналитического отчёта по данным experiments.tsv — траектория метрики, статистика экспериментов, топ-импакт, убывающая отдача, рекомендации.

---

## Входные параметры

| Параметр | Обязательный | По умолчанию | Описание |
|----------|-------------|--------------|----------|
| `slug` | Нет | последний PRD | Slug директории в MEMORY/WORK/ (имя папки) |

---

## Workflow

### Step 1: Найти experiments.tsv

**Если передан slug:**
```bash
# Точное совпадение по slug
ls ~/.claude/MEMORY/WORK/{slug}/experiments.tsv
```

**Если slug не передан:**
```bash
# Найти самый свежий experiments.tsv по дате модификации
ls -t ~/.claude/MEMORY/WORK/*/experiments.tsv | head -1
```

Если файл не найден — завершить с ошибкой: `experiments.tsv не найден. Укажите slug директории из MEMORY/WORK/.`

Также прочитать PRD.md из той же директории для контекста (task, phase, progress).

---

### Step 2: Парсинг experiments.tsv

Файл experiments.tsv содержит одну или несколько секций `[Q]`, разделённых заголовками.

**Формат заголовка секции:**
```
# [Q] ISC-N: описание
# metric_direction: lower_is_better | higher_is_better
# target: число
# think_reentries: число
# amplitude: normal | amplified | reduced
```

**Формат строки данных (TSV с заголовком колонок):**
```
iteration	commit	metric	delta	status	description
```

**Статусы строк:**
- `baseline` — начальное измерение (iteration 0)
- `keep` — эксперимент принят, метрика улучшилась
- `discard` — эксперимент отклонён, нет улучшения
- `crash` — эксперимент сломал сборку/тесты
- `skip` — эксперимент пропущен (не применим)
- `timeout` — эксперимент превысил тайм-лимит

**Комментарии в данных:**
- Строки начинающиеся с `#` внутри секции данных — это мета-комментарии (regression gates, stagnation markers и т.д.), пропускать при парсинге данных.

**Парсинг нескольких секций [Q]:**
При обнаружении нового заголовка `# [Q] ISC-N:` — начать новую секцию. Каждая секция анализируется независимо. Финальный отчёт содержит разделы для каждой секции.

---

### Step 3: Анализ траектории

Для каждой секции [Q]:

1. **Baseline** — значение metric из строки со status=baseline (iteration 0)
2. **Current** — значение metric из последней строки со status=keep. Если keep нет — текущее = baseline
3. **Total delta** = Current - Baseline
4. **Процент** = abs(Total delta / Baseline) * 100
5. **Направление:**
   - Если metric_direction = lower_is_better:
     - Current <= target → `цель достигнута`
     - Current < Baseline → `на пути к цели`
     - Current == Baseline (и есть > 3 итераций) → `стагнация`
   - Если metric_direction = higher_is_better:
     - Current >= target → `цель достигнута`
     - Current > Baseline → `на пути к цели`
     - Current == Baseline (и есть > 3 итераций) → `стагнация`

---

### Step 4: Таблица статусов

Для каждой секции [Q] подсчитать количество строк по каждому статусу (исключая baseline):

```
| Статус  | Количество | %   |
|---------|-----------|-----|
| keep    | N         | X%  |
| discard | N         | X%  |
| crash   | N         | X%  |
| skip    | N         | X%  |
| timeout | N         | X%  |
```

Показывать только статусы с количеством > 0. Процент от общего числа итераций (без baseline).

---

### Step 5: Топ-5 по импакту

Для каждой секции [Q]:

1. Отфильтровать строки со status=keep
2. Отсортировать по abs(delta) убыванию
3. Показать top-5 (или меньше, если keep < 5):

```
### Наибольший импакт

1. #1: remove zod from client ContactForm (delta: -268.8)
2. #2: fix Browser SKILL.md — cross-platform Chrome paths (delta: -2)
3. ...
```

Если keep = 0, написать: `Ни один эксперимент не был принят.`

---

### Step 6: Анализ убывающей отдачи

**Текстовая траектория:**

Показать milestone-маркеры — значения метрики на каждом keep-эксперименте:

```
Траектория: 1161.4 ──▶ 892.6 ──▶ [target: 900]
             #0        #1
```

Для более длинных серий (5+ keep) показать каждый keep:
```
Траектория: 11 → 9 → 6 → 5 → 4 → 3 → 0
             #1  #2  #3  #4  #5  #8
                                     [target: 0]
```

**Точка перегиба:**

Рассчитать только при >= 10 итераций (включая все статусы):

1. Взять все строки со status=keep, упорядоченные по iteration
2. Средний abs(delta) первых 10 keep-экспериментов = avg_early
3. Средний abs(delta) последних 10 keep-экспериментов = avg_late
4. Если avg_late < 50% * avg_early → убывающая отдача найдена
5. Точка перегиба = iteration первого keep из "поздней" группы

Вывод:
- Если найдена: `Убывающая отдача началась на итерации {N}. Средний delta упал с {avg_early} до {avg_late}.`
- Если не найдена или < 10 итераций: `Недостаточно данных для анализа убывающей отдачи.`

**Анализ по категориям:**

1. Сгруппировать эксперименты по ключевым словам из description (первые 2-3 слова или семантическая группа)
2. Для каждой категории: количество экспериментов, количество keep, суммарный delta
3. Найти категорию с наибольшим суммарным abs(delta) среди keep

Вывод:
```
### Категории экспериментов

| Категория           | Всего | Keep | Суммарный delta |
|---------------------|-------|------|-----------------|
| validation libs     | 1     | 1    | -268.8          |
| cross-platform fix  | 3     | 3    | -4              |
| tree-shaking        | 4     | 0    | 0               |

Наиболее эффективная категория: validation libs (delta: -268.8)
```

---

### Step 7: Формирование отчёта

Собрать итоговый отчёт. Если файл содержит несколько секций [Q], генерировать блок для каждой секции, затем общий итог.

**Формат для одной секции [Q]:**

```
═══ Autoresearch Report ══════════════════════════════
📊 PRD: {task из PRD.md}
📅 Дата: {текущая дата}

── [Q] {ISC-id}: {описание} ──────────────────────────

📊 Метрика: {direction} (целевое: {target})
🎯 Baseline: {baseline} → Current: {current}
📈 Прогресс: {delta} ({pct}%) — {направление}

### Траектория
{текстовая траектория из Step 6}

### Распределение статусов (N итераций)
{таблица из Step 4}

### Наибольший импакт
{top-5 из Step 5}

### Убывающая отдача
{анализ из Step 6}

### Категории экспериментов
{таблица категорий из Step 6}
```

**Общий итог (после всех секций):**

```
── Итог ──────────────────────────────────────────────

| [Q] | Цель | Baseline | Current | Delta | Статус |
|-----|------|----------|---------|-------|--------|
| ISC-1 | < 220 | 259.7 | 259.7 | 0.0 | стагнация |
| ISC-2 | < 5 | 12 | 9 | -3 | на пути к цели |

💡 Рекомендации:
- {рекомендация 1 — основана на данных}
- {рекомендация 2 — основана на данных}
- {рекомендация 3 — если применимо}
```

**Правила генерации рекомендаций:**

1. Если `цель достигнута` → `Цель {ISC-id} достигнута. Зафиксировать результат, перейти к следующей задаче.`
2. Если `на пути к цели` и keep-rate > 30% → `Продолжить итерации — высокий процент успешных экспериментов.`
3. Если `на пути к цели` и keep-rate < 15% → `Пересмотреть подход — низкий процент успешных экспериментов. Возможно нужен L3 (структурный) подход.`
4. Если `стагнация` → `Стагнация. Рассмотреть: (a) повышение amplitude, (b) L3 структурный подход, (c) пересмотр target.`
5. Если crash-rate > 20% → `Высокий процент crash-экспериментов ({N}%). Улучшить verify-скрипт или ужесточить ограничения.`
6. Если есть убывающая отдача → `Убывающая отдача с итерации {N}. Дальнейшие итерации в текущем подходе нерентабельны.`
7. Если одна категория доминирует по импакту → `Категория "{name}" показала наибольший импакт. Фокусировать дальнейшие эксперименты в этом направлении.`

---

### Step 8: Синтез с LEARN.md (для завершённых PRD)

Проверить поле `phase` в YAML-frontmatter PRD.md. Если `phase: complete`:

1. Прочитать LEARN.md из той же директории
2. Добавить в отчёт секцию:

```
── Синтез обучения ───────────────────────────────────

### Рефлексии
{содержимое секции Reflections из LEARN.md}

### Паттерны
{содержимое секции Patterns из LEARN.md}

### Действия
{содержимое секции Actions из LEARN.md}

### Связь с экспериментами
{1-3 предложения связывающих данные экспериментов с выводами из LEARN.md}
```

Секция "Связь с экспериментами" генерируется на основе анализа:
- Какие паттерны из LEARN.md подтверждаются данными experiments.tsv
- Какие рефлексии соответствуют распределению статусов
- Какие действия следуют из траектории метрики

## Обработка крайних случаев

1. **Пустой experiments.tsv (только заголовки, нет данных):** Вывести `Нет данных для анализа. Эксперименты ещё не начаты.`
2. **Только baseline, нет итераций:** Вывести baseline и сообщение `Только baseline. Эксперименты не проводились.`
3. **Все итерации discard/crash:** Вывести нулевой прогресс с рекомендацией пересмотреть подход.
4. **Несколько секций [Q] с разными направлениями:** Каждая секция анализируется по своему direction. Итоговая таблица содержит все секции.
5. **Комментарий STAGNATION STOP:** Отметить в отчёте: `Автоматическая остановка по стагнации на итерации {N}.`
6. **Нет PRD.md в директории:** Пропустить данные PRD, генерировать отчёт только по experiments.tsv.
